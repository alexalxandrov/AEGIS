# AEGIS — Roadmap (v2)

Оценки сроков — для одного разработчика, примерно 10–15 часов в неделю, и содержат запас. Прежняя версия оценивала по «чистому времени» и была слишком оптимистичной. Если не успеваете — сокращайте объём фазы, а не качество подтверждений.

Правила прохождения:
- Фаза закрыта только когда выполнены **критерии готовности**.
- На контрольных точках (GATE) принимается решение «идти дальше / менять курс / остановиться».
- Ничего из `concept.txt → Анти-скоуп` в roadmap не добавляется.

---

## PHASE 0 — Фундамент и проверка реальности (1–2 недели)

- [ ] Репозиторий, `docker compose` (app + postgres + ollama), конфиг, логирование
- [ ] **Проверка LLM на вашем железе:** какая модель запускается, скорость, качество на тестовом finding
- [ ] БД: `Organization`, `Seed`, `Asset`, `Observation`, `Edge`, `Finding`, `Task`, `SourceHealth`
- [ ] Очередь задач на Postgres (`SKIP LOCKED`) + планировщик
- [ ] **Scope-ядро:** статусы `VERIFIED/CANDIDATE/THIRD_PARTY/OUT_OF_SCOPE`, отказ запуска active-щупальца вне `VERIFIED`, журнал действий
- [ ] Реестр источников: лимиты, ToS/лицензия, health-check; **проверка, какие бесплатные источники реально работают сейчас**
- [ ] Контракт `Tentacle` + пустой пример

**Готово, когда:** `docker compose up` поднимает всё; `aegis check` показывает, какая LLM работает и какие источники живы; попытка активной пробы по не-`VERIFIED` активу отклоняется.

---

## PHASE 1 — Пассивная разведка (2–3 недели)

- [ ] CT: crt.sh + кэш/ретраи
- [ ] DNS: несколько резолверов, сравнение ответов, **начало собственной истории DNS**
- [ ] RDAP (домен и IP), BGP/ASN (RIPEstat, Team Cymru, PeeringDB)
- [ ] Shodan InternetDB (по IP), Wayback CDX, Common Crawl index
- [ ] GitHub-поиск (упоминания хостов; секреты — маскировать)
- [ ] Репутационные фиды (abuse.ch, DNSBL низкий объём)
- [ ] Нормализация, дедуп, правило записи «наблюдение только при изменении + last_confirmed»
- [ ] Атрибуция: `existence_confidence` и `attribution_confidence`; стоп-лист CDN/облаков; лимит глубины pivoting
- [ ] Граф: `Domain → Subdomain → IP → ASN`, `Certificate`

**Готово, когда:** по seed-домену получаем граф с уверенностями; повторный прогон не плодит дубликаты наблюдений; видно, какие источники дали что.

---

## PHASE 2 — Активная разведка, минимально необходимая (3–4 недели)

Принцип: **не писать то, что уже есть** в open-source. Обёртки и простые собственные зонды.

- [ ] DNS-перебор (subfinder/dnsx + пермутации + wildcard-детект)
- [ ] Порты: обёртка naabu/nmap, top-1000, rate-limit
- [ ] TLS-зонд (цепочка, SAN, CA, сроки, протоколы)
- [ ] HTTP-зонд (заголовки, редиректы, title, favicon-hash, методы)
- [ ] Технологии (сигнатуры) → кандидаты CPE
- [ ] Безопасные проверки: nuclei (безопасные категории), takeover-отпечатки, наличие чувствительных путей **без сохранения содержимого**
- [ ] Почтовая политика (MX/SPF/DKIM/DMARC/MTA-STS)
- [ ] Облачные кандидаты: проверка публичности корня без скачивания
- [ ] Lookalike-домены (генерация + DNS + CT)
- [ ] Краулер (минимальный, вежливый)
- [ ] Хранилище доказательств (сжатие, хэш, срок хранения)
- [ ] Честный User-Agent, rate-limit на хост, фиксированный исходящий IP

**Готово, когда:** по `VERIFIED` цели получаем порты/сервисы/TLS/HTTP с доказательствами; нагрузка на цель укладывается в заданные лимиты; чужие (CDN/third-party) хосты активно не трогаются.

---

## PHASE 3 — Граф + история + diff (2 недели)

- [ ] Корреляция между источниками, агрегация уверенности по классам источников
- [ ] Жизненный цикл актива (`first_seen`, `last_seen`, `is_alive`, TTL)
- [ ] Запросы «состояние на дату» и **diff двух дат**
- [ ] «Машина времени» по активу (API)
- [ ] Классификация изменений (новое/пропало/изменилось)

**Готово, когда:** на тестовой цели через несколько дней видно осмысленный diff; можно ответить «что изменилось с понедельника».

### 🚦 GATE A — «работает ли разведка на живых целях» (после Phase 3)

Прогнать на 3–5 реальных доменах (собственные и с разрешением). Проверить:
- нашлось ли что-то, чего вы не знали;
- сколько ложных срабатываний/шума;
- нагрузка на цель и на вас (время, железо).

Решение: продолжать / упрощать (убрать шумные щупальца) / остановиться.

---

## PHASE 4 — AI Analyst v1 (2–3 недели) — LLM в ядре, раньше остального

- [ ] Подготовка структурированного входа (нормализованные поля, обрезка, экранирование недоверенных данных)
- [ ] Дайджест за сутки/неделю
- [ ] Объяснение finding (что/почему/что проверить)
- [ ] **Валидатор цитат:** ID существуют, числа и даты совпадают
- [ ] Чат поверх графа через **белый список read-only функций**
- [ ] LLM в разведке: генерация кандидатов имён → очередь проверки DNS; классификация неизвестных HTTP-страниц как `llm_hypothesis`
- [ ] Тесты на prompt-injection (страницы/баннеры с «инструкциями»)

**Готово, когда:** дайджест по реальной цели читается без правок и все утверждения прослеживаются до наблюдений; модель не выполняет инструкции из данных; ответ «в данных нет» работает.

---

## PHASE 5 — Расписание, мониторинг, доставка (2 недели)

- [ ] Каденции по типам проб и критичности активов
- [ ] Генерация findings из изменений (правила)
- [ ] Алерты: Telegram, e-mail (свой SMTP), webhook
- [ ] Минимальный интерфейс: статус, изменения за сутки, карточка актива, чат
- [ ] Дайджест по расписанию

**Готово, когда:** система работает неделю без вмешательства, присылает дайджест и алерты, не заваливая шумом.

### 🚦 GATE B — «нужно ли это кому-то кроме меня» (после Phase 5, MVP готов)

Выполнить план из `competitors_analyse.txt → раздел 7`. Решение: развивать как продукт / как инструмент для себя / переосмыслить.

---

## PHASE 6 — Risk Engine на открытых данных (2 недели)

- [ ] NVD (бесплатный ключ), KEV, EPSS, OSV
- [ ] Классы доказательства `CONFIRMED / PROBABLE / POSSIBLE`
- [ ] Критичность актива (экспозиция, админ-панель, роль)
- [ ] Расчёт приоритета с **разложением причин**
- [ ] Жизненный цикл finding

**Готово, когда:** у каждого finding есть класс доказательства и объяснение приоритета; совпадение версии без проверки не уходит выше `HIGH`.

---

## PHASE 7 — Baseline и аномалии (2 недели)

- [ ] Базовый снимок после начального периода
- [ ] Робастные статистики (медиана/MAD), скорость изменений
- [ ] Правила отклонений («нетипично для организации»)
- [ ] Обзор baseline в интерфейсе

**Готово, когда:** «новый актив вне нормы» срабатывает на реальных примерах и не срабатывает на обычных колебаниях.

---

## PHASE 8 — Мониторинг доступности (1–2 недели)

- [ ] Пробы: TCP/TLS/HTTP/DNS по расписанию
- [ ] Временные ряды, baseline по p50/p95
- [ ] Классы: `REACHABILITY_LOSS`, `LATENCY_DEGRADATION`, `TLS_FAILURE`, `HTTP_ERROR_SPIKE`, `DNS_ANOMALY`
- [ ] LLM формулирует гипотезы **с явным «чего мы не знаем»**
- [ ] Вторая точка наблюдения (опционально, если появится бесплатный хост)

**Готово, когда:** сбой цели фиксируется как факт, а не как «обнаружена DDoS»; нет заявлений о причинах, которые снаружи не доказать.

---

## PHASE 9 — Верификация и жизненный цикл (1–2 недели)

- [ ] Рабочий процесс: «исправлено» → целевая перепроверка
- [ ] Состояния: `open / fixed-unverified / verified / failed / stale`
- [ ] Журнал действий для аудита

**Готово, когда:** закрытый порт/замена сертификата подтверждается автоматически; провал исправления открывает finding заново.

---

## PHASE 10 — Отчёты и закалка (постоянно)

- [ ] Экспорт отчётов (Markdown/HTML/PDF), executive summary
- [ ] Резервные копии, retention доказательств, удаление данных организации
- [ ] Наблюдаемость (метрики Prometheus, структурные логи)
- [ ] Производительность, нагрузочные пределы
- [ ] Юридическая сверка: ToS источников, лицензии тулзов, правила для чужих целей
- [ ] Multi-tenant — только если GATE B скажет «да»

---

## Сводка сроков

| Этап | Оценка |
|---|---|
| Phase 0–3 (разведка + граф + история) | ≈ 2,5–4 месяца |
| Phase 4–5 (LLM + мониторинг + доставка = MVP) | ≈ 1–1,5 месяца |
| Phase 6–9 | ≈ 2–3 месяца |
| Итого до полной версии | ≈ 6–9 месяцев при 10–15 ч/нед |

Если нужен более быстрый путь к MVP: сделайте **минимальные версии** Phase 1–3 (только CT + DNS + HTTP/TLS + простой diff), затем сразу Phase 4–5, и только потом возвращайтесь за остальными щупальцами.

---

## Что в roadmap сознательно нет

DDoS-«защита» и классификация атак, клиентские сенсоры, интеграции с WAF/CDN для воздействия, ротация прокси, утечки учётных данных/даркнет, собственный Internet-wide сканер, платные подписки как зависимость.
