# STEP_BY_STEP.txt

## Разделение concept.txt
1. Откройте файл **concept.txt**.
2. Прочитайте заголовок и миссию (секция `## 0. Миссия`).
3. Для каждой секции (`##`) запишите название секции и краткое содержание (1–2 строки).
4. Переведите каждую секцию в отдельную задачу: *Написать план реализации для секции 1*.
5. Для каждой задачи определите подзадачи: исследование, написание кода, тесты, документация.
6. Составьте список задач в порядке приоритета (см. миссию → основные принципы → реализация).

## Разделение текущей реализации
1. Выполните `ls -laR .` (вывод сохранён ниже для справки).
2. Сформируйте общий обзор структуры:
   - Корневые файлы: `concept.txt`, `roadmap.txt`, `README.md`, `requirements.txt`, `tests`, `aegis`, `fastapi`, `data`, `docs`, `network_scan.*`, `pytest`, etc.
3. Для каждой папки/модуля:
   - `aegis/`: основные файлы (`__init__.py`, `cli.py`, `runner.py`, `orchestrator.py` и другие).
     Задачи: изучить функциональность, написать/обновить тесты, refactor, добавить документацию.
   - `tests/`: проверить покрытие, добавить недостающие тесты.
   - `fastapi/`: проверить API, написать эндпоинты, проверить интеграцию.
   - `data/`, `docs/`: проверить корректность данных/документации.
   - `network_scan.*`: проверить утилиты и команды.
4. Для каждого ключевого файла составьте список подзадач: чтение кода, документирование, тестирование, refactor, покрытие.

## Общий список супер‑микрозадач
- Открыть **concept.txt**.
- Считать заголовок и миссию.
- Составить список секций.
- Для каждой секции: создать задачу, подзадачи.
- Выполнить `ls -laR .`.
- Список файлов/директорий.
- Для каждого компонента: задать задачи.
- Сформировать итоговый список.
