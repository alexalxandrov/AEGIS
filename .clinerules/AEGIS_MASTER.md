# AEGIS — MASTER RULES

## 🔴 ПЕРВОЕ ДЕЙСТВИЕ ПРИ СТАРТЕ

**ПЕРЕД любыми изменениями в коде — прочитать ЛОКАЛЬНЫЕ папки и файлы проекта С САМОГО НАЧАЛА.**

Обязательный порядок чтения:
1. `concept.txt` — продуктовая концепция (САМОЕ ПЕРВОЕ)
2. `first_idea.txt`
3. `competitors_analyse.txt`
4. `roadmap.txt`
5. `README.md`
6. `RUN.md`
7. `IMPLEMENTATION_STATUS.md` (если существует)
8. Полная структура `aegis/` и `tests/`
9. `git status`, `git log`, содержимое последнего коммита

**Первым выводом после этого промпта должно быть просто слово: ГОТОВ**

## 📌 КОНТЕКСТ

AEGIS — Autonomous External Graph Intelligence System.
Локальная система EASM/OSINT-разведки цифрового периметра организации.
Работаем **ТОЛЬКО с локальной папкой проекта**. Никаких удалённых репозиториев без явного разрешения.

## 🚫 АБСОЛЮТНЫЕ ЗАПРЕТЫ

- Docker запрещён полностью (никаких Dockerfile, docker-compose, devcontainers)
- Не запускать LLM локально на Mac — Ollama может быть на отдельном Linux-ПК
- Не выполнять `git reset --hard`, force push, переписывание истории
- Не удалять локальную SQLite БД, кэш, конфигурацию без бэкапа
- Не выполнять реальные сетевые сканирования реальных целей
- Не коммитить секреты, API-ключи, приватные данные
- Не переписывать существующие модули без доказанной необходимости

## ✅ РАЗРЕШЕНО

- Сеть РАЗРЕШЕНА (AEGIS — сетевой инструмент)
- Локальная папка проекта — единственная рабочая среда
- SQLite как основная БД по умолчанию
- Python + FastAPI backend, React + TypeScript + Vite frontend
- Внешняя Ollama по HTTP
- Обычные Python-пакеты и нативные CLI-бинарники (subfinder, dnsx, httpx, nuclei, katana, naabu)

## 📋 ПРОЦЕСС РАБОТЫ

1. Проверить `git status`, текущую ветку, последние коммиты
2. Прочитать обязательные документы (см. блок «ПЕРВОЕ ДЕЙСТВИЕ»)
3. Изучить `IMPLEMENTATION_STATUS.md`, если есть
4. Аудит: найти TODO, заглушки, ошибки импортов, неработающие маршруты API, неиспользуемые компоненты
5. Запустить доступные тесты и сборки (без реальных сканирований)
6. Создать/обновить `IMPLEMENTATION_STATUS.md` с приоритетами
7. Работать небольшими логическими этапами
8. После каждого этапа — запускать проверки, сохранять рабочее состояние
9. При исчерпании лимита — оставить проект в согласованном состоянии и записать точный следующий шаг
